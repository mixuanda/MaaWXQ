# Third-party sources, dependencies and licenses

Reviewed against official license text on 2026-10-17. **MaaWXQ's own license has not been selected.** Public visibility is not an open-source license grant. This inventory distinguishes factual/design references, an optional runtime dependency, and third-party binaries present only in a private local download. It is not a legal opinion or a declaration that a future binary distribution is compliant.

## Tracked-source audit

The initial tracked prototype and T1 additions are original project source, synthetic tests/fixtures and documentation. No MAA, BetterGI or MaaFramework implementation source was copied or adapted into the repository; the adapter declares the published Win32/MaaFramework C ABI and calls it through Python `ctypes`. No upstream logo, game image, model, template, executable or library is tracked. The shared game strings identify UI/domain labels.

The core offline prototype uses the Python standard library and Windows APIs. The WGC adapter optionally loads a locally downloaded MaaFramework shared-library runtime; it does not import the MaaFramework Python binding or install its declared `maaagentbinary`, `numpy` or `strenum` dependencies. Local runtime directories and all DLLs are ignored by Git.

## Optional runtime provenance

`capture-runtime.lock.json` identifies the official PyPI Windows x64 wheel, fixed version, download URL and SHA-256. `prepare_capture_runtime.py` verifies it and extracts it under ignored `local/`; no pip/global install, driver install or system setting change occurs. The original wheel license is retained locally at `maafw-5.7.2.dist-info/licenses/LICENSE.md`.

Version 5.7.2 is intentionally selected because its [controller manager](https://github.com/MaaXYZ/MaaFramework/blob/v5.7.2/source/MaaWin32ControlUnit/Manager/Win32ControlUnitMgr.cpp) creates plain `FramePoolScreencap`. The reviewed 5.14.3 manager instead selects a pseudo-minimize wrapper. This is a behavioral pin, not a claim that the old release is the latest or has a current security-support guarantee. Upgrades require a fresh code/behavior review.

## Project-license decision and release limits

One maintainer decision is still required: choose a license for MaaWXQ's original code/documentation. A permissive license such as MIT or Apache-2.0 is a reasonable candidate for independently written code using an LGPL shared library, subject to satisfying upstream terms. Strong-copyleft reuse from MAA/BetterGI would change that review. This is a compatibility direction, not an automatic license choice or legal guarantee; no `LICENSE` file is added without the owner's decision.

Before distributing executables or combined binaries, retain appropriate license texts/copyright/NOTICE material, identify modified upstream files and corresponding source, resolve transitive terms including DirectML, and document replacement/relinking with interface-compatible library builds. The prototype's strict provenance guard intentionally accepts only the reviewed runtime; a distributable combined build needs a suitable documented replacement/relinking path rather than treating that guard as LGPL compliance. No binary release is currently offered.
